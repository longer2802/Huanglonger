# 辦公室揪訂

幫辦公室同事一起訂午餐、下午茶，或兩者一起訂的手機網頁 App。

主揪先拍菜單照片（或貼上文字、手動建立），再輸入同事名單，App 會產生每人一列的點餐表，自動算好每人應收、各店家小計和全單總額。最後可以匯出兩種單：

- **給店家的訂單**：PNG／PDF
- **內部收款單**：PNG／PDF

整個 App 不用登入、不用後端、不用金鑰，也不使用付費服務。執行時不呼叫 LLM、付費 OCR、雲端語音或雲端資料庫。

## 啟動

需要 Node.js 18 以上。

```bash
npm install
npm run dev        # 開發模式，http://localhost:5173
npm test           # 單元測試（金額計算、菜單解析、名單切分）
npm run build      # 產出 dist/
npm run preview    # 在本機預覽 dist/，http://localhost:4173
```

## 靜態部署

`npm run build` 產生的 `dist/` 是純靜態檔案，可以直接放到任何靜態主機，例如 GitHub Pages、Netlify、Cloudflare Pages、Nginx 或公司內部的檔案伺服器。

- 使用相對路徑（`base: "./"`），放在網站根目錄或任何子目錄都能運作。
- 必須用 **https** 或 `localhost` 開啟。拍照、分享和剪貼簿都需要安全連線。
- 不需要任何伺服器端設定或環境變數。

`dist/` 約 17 MB，大部分是菜單辨識用的檔案：

| 檔案 | 說明 | 何時載入 |
| --- | --- | --- |
| `assets/index-*.js`、`*.css` | App 本體（約 80 KB gzip） | 開啟首頁時 |
| `assets/worker.min-*.js`、`assets/tesseract-core-*-lstm.wasm-*.js` | Tesseract.js 的 worker 和 WASM 引擎，依瀏覽器支援度只會載入其中一個 | 第一次按「辨識」時 |
| `ocr-lang/chi_tra.traineddata.gz`、`ocr-lang/eng.traineddata.gz` | 繁體中文與英文字庫，共約 4.6 MB | 第一次按「辨識」時，之後存在瀏覽器裡 |
| `assets/jspdf*.js` | PDF 產生器 | 第一次匯出 PDF 時 |

這些檔案都跟網站放在一起，不從 CDN 下載。首頁不會載入任何 OCR 檔案；要等使用者按下「辨識」才會載入。

## 使用流程

1. **訂單與菜單**
   - 填寫訂單名稱、日期，勾選要訂餐點、飲料或兩者，並填店家名稱。
   - 菜單有四種建立方式：
     - **📷 拍照**、**🖼 上傳照片**（可一次選多張 JPG／PNG），再按「辨識」。大圖會先等比例縮到長邊 1800px 再辨識。
     - **📋 貼上文字**：從 LINE 或網頁複製菜單文字。
     - **＋ 手動新增品項**：可以完全不用辨識，手動建立整份菜單。
   - 辨識或貼上後會打開「校對候選清單」：
     - 每個品項的分類、品名、規格、單價都可以修改。手機上可以切換「原圖」和「校對表」對照。
     - 大小杯等不同價格會拆成不同規格。
     - 多欄排版、套價、模糊數字、配對不明的品項會標成「待確認」。
     - 缺價的品項有紅框。缺價品項不會出現在點餐選項，也不會出單，所以要補上價格或刪除。
     - 0 元必須手動輸入「0」，系統會和「缺價」分開處理。
   - 校對好的菜單可以「存成店家模板」，下次叫同一家直接載入。
2. **名單**
   - 可以打字、從群組貼上多行名單，或用手機鍵盤的麥克風聽寫。換行、逗號、頓號都會自動切開。
   - 建立前會先預覽。遇到同名的人會提示，可以加上「辨識標記」（例如「業務部」）。每個人在系統內都有獨立 ID，同名也不會混在一起。
3. **點餐**
   - 每個人可以點多項餐點和飲料，每項都能填數量和備註。飲料可以選大小杯、甜度、冰量和加料。
   - 會影響價格的規格或加料一定要有金額。
   - 桌機用表格顯示；手機用摘要列，點一下展開編輯。
   - 每個人會顯示「待填／已完成／不訂」三種狀態之一。
   - 編輯時會自動存草稿，重新整理或關掉再開都會回到原畫面。
4. **總計收款**
   - 顯示每人應收、各店家合計和全單總額。
   - 可以逐人勾選「已收」，並即時顯示已收和待收金額。
   - 先按「預覽核對」，確認後再「確認並儲存正式訂單」。
5. **匯出**
   - 有「給店家」和「內部收款」兩種預覽，都能直接下載 PNG 和 PDF。手機支援時也可以用系統分享。
   - 店家單會依店家分開，逐人明細可以切換顯示姓名或編號。如果餐點和飲料是同一家店，會合併在同一份單。
   - 長單 PDF 會依完整的列分頁，每頁重複表頭。PNG 太長時會切成多張，並標上「第 n 頁」。
   - 檔名範例：`午餐_幸福便當_店家單_2026-11-25.pdf`、`午餐_內部收款單_2026-11-25.png`。

首頁的「載入範例」會建立一張明確標示「範例」的訂單，內容是：

- 阿榮：雞腿便當 110 元，鮮奶茶大杯 55 元加珍珠 10 元，應收 175 元。
- 小妤：排骨便當 95 元兩份，紅茶 40 元，應收 230 元。
- 小陳：不訂。

全單合計：餐點店家 300 元、飲料店家 105 元、全單 405 元。

## 菜單辨識怎麼運作

適用各種菜單版面，包括深色底、多欄、附英文副標和食物照片的海報式菜單：

1. **影像處理**：把照片縮放到長邊約 2400px，小圖會放大。深色底淺色字會自動反白，再拉高對比。
2. **只用繁體中文模型辨識**：英文副標不需要辨識。同時用英文模型反而會把中文行誤認成英文。
3. **依位置整理**（`src/lib/ocrLayout.ts`）：
   - 只保留以中文為主的行和 2～4 位數的價格。英文副標、照片雜訊、店名標語、電話、地址、營業時間都會略過。
   - 每個品名會配上正下方同一欄、或同一列右邊最近的價格。
   - 括號開頭的附註（例如「(使用某某肉)」）不會被當成品名。
   - 價格多讀一位數時，會依同一張圖的數字寬度修正。
4. **飲料單**：
   - 同一列的多個價格（中杯／大杯、M／L）都會收進同一個品名，並依上方的「中杯 大杯」「M L」表頭標上規格。
   - 也支援「M35 / L45」「35/45」寫法，以及左右並排的兩個表格。
   - 「加料：珍珠 +10」會變成加料選項；「甜度冰塊可調整」這類說明會略過。
5. **多種辨識方式擇優**：同一張照片會依需要嘗試不同的字高縮放、只反白深色標題色塊、表格模式，選配到最多價格的結果。信心不足的價格會只限數字再讀一次。
6. **低信心標示**：辨識信心低的品名或價格會標「待確認：辨識信心低」，請對照原圖修正。

## 金額規則

所有畫面、店家單和收款單都使用同一套計算（`src/lib/pricing.ts`）：

- 台幣一律用整數計算。
- **品項小計 =（單價 + 每份加料加價）× 數量**。
- 不接受空白價格、負數、小數價格，以及不是正整數的數量。
- 每筆點餐明細都會存下當時的品名、規格和單價。之後修改店家模板或菜單，已點的金額不會跟著改。
- 店家彙總時，品名、規格、甜度、冰量、加料、客製備註全部相同才合併，做法不同就分開列。

## 語音輸入

- App 只有在瀏覽器能**確認 zh-TW 語音可以在裝置上辨識**時，才會顯示「🎤 語音輸入（裝置端）」按鈕。確認方式是 `SpeechRecognition.available({ langs: ["zh-TW"], processLocally: true })` 回傳 `"available"`。
- 使用時會強制 `processLocally = true`，所以聲音不會送到雲端。
- 目前支援這個 API 的主要是較新版本的 Chrome。即使瀏覽器支援，也必須已經下載 zh-TW 的裝置端語音模型，按鈕才會出現。
- 無法確認時（例如 iPhone Safari、Firefox、舊版 Chrome），App 不會顯示語音按鈕，也不會改用瀏覽器的雲端語音。這時畫面會提示改用：
  - **鍵盤聽寫**：點名單輸入框，按 iPhone 或 Android 鍵盤上的麥克風，一次說一個名字，說完換行。
  - **貼上**：從群組或試算表複製名單貼上。
- 自動化測試瀏覽器（`navigator.webdriver`）一律視為不可用。原因是部分無頭瀏覽器呼叫 `available()` 時會讓整個分頁當掉。

## 資料存放、備份與還原

- 菜單照片、名單、訂單、收款狀態和店家模板，都存在**這台裝置的這個瀏覽器**（IndexedDB），不會上傳。
- 換手機、換瀏覽器、使用無痕模式，或清除網站資料，資料都會消失或看不到。
- **備份**：到首頁「資料備份」按「匯出 JSON 備份」。可以選擇是否包含菜單照片；包含照片的檔案會比較大。
- **還原**：在新的瀏覽器開啟 App，按「匯入還原」並選擇備份檔。同一個 ID 的訂單和模板會被備份內容覆蓋，其他資料保留。
- 辨識字庫第一次下載後會快取在瀏覽器裡，之後辨識不用重新下載。

## 專案結構

```
src/
  lib/
    pricing.ts      金額計算（唯一來源）、驗證、店家彙總
    menuParser.ts   OCR／貼上文字 → 候選品項的規則
    ocr.ts          Tesseract.js（按下辨識才動態載入）
    speech.ts       裝置端語音偵測
    names.ts        名單切分與同名偵測
    exportDoc.ts    A4 頁面排版（Canvas）→ PNG／PDF
    db.ts           IndexedDB 存取、JSON 備份與還原
    orders.ts       訂單工具與範例資料
  components/       各步驟畫面
  test/             單元測試（vitest）
e2e/                Playwright 實測腳本與測試菜單圖
```

## 端對端測試

```bash
npm run build && npm run preview &
python3 e2e/make-menu.py            # 產生測試用繁中菜單照片（需要 Pillow 和中文字型）
node e2e/ocr.e2e.cjs               # 上傳照片 → 辨識 → 校對
node e2e/flow.e2e.cjs              # 完整流程：辨識、模板、名單、點餐、重整還原、收款、匯出
node e2e/acceptance.e2e.cjs        # 範例金額、長名單跨頁、桌機表格、備份還原
```

如果下載的中文檔名變成 `download`，代表執行環境缺少 UTF-8 locale。測試腳本已經用 `LANG=C.UTF-8` 啟動瀏覽器來避免這個問題。
